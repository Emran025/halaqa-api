# قواعد وضع الملفات واتخاذ القرار

## قاعدة عامة

ضع كل ملف في الطبقة التي تعبر عن مسؤوليتها الوحيدة. لا تُنشئ طبقة جديدة لمجرد اتباع نمط شائع؛ أنشئها عندما تمنع تكرارًا أو تعزل تعقيدًا أو تحسن الاختبار.

| الملف أو المفهوم | المسار المعياري | المسؤولية | ما يجب منعه |
|---|---|---|---|
| Controller | `app/Http/Controllers/Api/V1` | تنسيق دورة HTTP: Request ثم Policy ثم Service/Query ثم Resource. | SQL، حلقات الأعمال، استدعاءات خارجية، وعمليات طويلة. |
| Form Request | `app/Http/Requests/Api/V1` | التحقق من شكل المدخلات وتفويض الطلب الأولي. | تعديل Models، حفظ البيانات، وقواعد الأعمال المركبة. |
| API Resource | `app/Http/Resources/Api/V1` | تحديد شكل JSON وإخفاء الحقول وتنسيق العلاقات. | الاستعلام، الحفظ، الإرسال إلى WebSocket، وقواعد القرار. |
| Service | `app/Services` | تنفيذ حالة استخدام متعددة الخطوات أو ذات قواعد عمل. | الاعتماد على `Request` و`JsonResponse` أو إعادة HTML/JSON مباشرة. |
| Query Service | `app/Queries` | قراءة مركبة أو تقريرية تحتاج أكثر من Model أو شروطًا متعددة. | عمليات الحفظ أو تغيير الحالة. |
| Model | `app/Models` | العلاقات، casts، scopes، وعمليات قريبة من البيانات. | منطق حالة استخدام كامل أو تنسيق API. |
| Policy | `app/Policies` | قرار السماح على مورد أو علاقة. | التحقق من شكل البيانات أو تنفيذ العملية. |
| Job | `app/Jobs` | تنفيذ مؤجل، طويل، أو قابل لإعادة المحاولة. | إخفاء عملية غير منظمة أو الاعتماد على اتصال HTTP حي. |
| Event | `app/Events` | إعلان أن حدثًا وقع. | تنفيذ كل منطق الأعمال داخل الحدث. |
| Listener | `app/Listeners` | الاستجابة لحدث بطريقة مفصولة. | إعادة تنفيذ العملية الأصلية أو إخفاء الفشل. |
| Notification | `app/Notifications` | إرسال تنبيه لقناة أو مستخدم. | تعديل البيانات الأساسية دون Service. |
| Integration Client | `app/Support/Integrations` | تغليف عميل REST أو خدمة خارجية متكررة. | وضع تفاصيل HTTP الخارجي داخل Controller. |
| DTO/Data | `app/Support/Data` | نقل قيم منظمة بين الطبقات عند الحاجة. | تحويل DTO إلى طبقة تخزين أو استجابة تلقائيًا دون قرار واضح. |
| Enum | `app/Enums` | قيم محددة مثل حالة الجلسة أو نوع الخطأ. | استخدام نصوص مكررة غير موحدة في كل الطبقات. |
| Migration | `database/migrations` | إنشاء أو تعديل بنية قاعدة البيانات. | إنشاء الجداول أثناء طلب HTTP. |
| Test | `tests/Feature` أو `tests/Unit` | إثبات سلوك HTTP أو وحدة منطقية. | اعتبار نجاح تنفيذ المسار دليلًا كافيًا دون اختبار حالات الفشل. |

## شجرة القرار

اسأل بالترتيب:

1. هل الملف يستقبل HTTP ويربط المدخلات بالنتيجة؟ ضعه في Controller.
2. هل الغرض الأساسي التحقق من البيانات أو التفويض الأولي؟ ضعه في Form Request.
3. هل الغرض تحديد شكل JSON؟ ضعه في Resource.
4. هل العملية قراءة فقط لكنها مركبة أو تقريرية؟ استخدم Query Service.
5. هل العملية تغير حالة أو تنفذ أكثر من خطوة أو تستخدم أكثر من Model؟ استخدم Service.
6. هل العملية طويلة أو لا تحتاج نتيجة فورية؟ استخدم Service + Job.
7. هل القرار متعلق بملكية مستخدم لمورد؟ استخدم Policy.
8. هل الحدث يجب بثه أو إرساله إلى مستمع؟ استخدم Event وBroadcast/Listener.
9. هل يتكرر اتصال خارجي؟ أنشئ Integration Client تستدعيه Service.

## معيار استخدام Service

استخدم Service عندما يتحقق شرط واحد مهم على الأقل: العملية تجمع أكثر من Model، أو تتضمن Transaction، أو تحتوي تفرعات حالة، أو تُستدعى من أكثر من Controller/Command/Job، أو تحتاج إلى API خارجي، أو يجب اختبارها بمعزل عن طبقة HTTP، أو تمثل فعلًا واضحًا في المجال.

لا تستخدم Service لعملية بسيطة مثل `findOrFail` ثم `return Resource` إذا لم توجد قواعد إضافية. في هذه الحالة يكفي Controller نحيف مع Policy وResource عند الحاجة.

## معيار استخدام Query Service

استخدم Query Service للتقارير وقوائم البحث التي تحتوي joins أو eager loading متدرج أو filters متعدّدة أو تجميعًا أو pagination مركبة. اجعلها للقراءة فقط، وسمِّها باسم النتيجة أو التقرير مثل `TeacherSessionReportQuery`.

## معيار استخدام Job

استخدم Job عندما يتوقع أن يتجاوز التنفيذ زمن طلب HTTP، أو يحتاج إلى retries، أو يعالج عددًا كبيرًا من السجلات، أو يرسل إشعارات متعددة، أو يستدعي خدمة خارجية ببطء. يجب أن يكون Job قابلًا لإعادة التنفيذ بأمان، وأن يكون الجزء الأساسي من قواعد الأعمال داخل Service قابلة للاختبار.

## نمط مسار البيانات

```text
HTTP Request
    -> Form Request
    -> Policy / Authorization
    -> Controller
    -> Service أو Query Service
    -> Model / Integration / Event
    -> API Resource
    -> JSON Response
```

في العمليات الفورية:

```text
Controller
    -> Service
    -> حفظ الحدث الرسمي في قاعدة البيانات
    -> Event / Broadcast إلى قناة مصرح بها
    -> WebRTC أو WebSocket عند الحاجة
    -> Resource للاستجابة الحالية
```
