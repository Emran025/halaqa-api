# قائمة التحقق المعمارية

## قبل التعديل

| السؤال | النتيجة المطلوبة |
|---|---|
| هل تمت قراءة شجرة المشروع الفعلية؟ | نعم، مع تسجيل الأمر والمجلدات ذات الصلة. |
| هل حُددت حالة الاستخدام؟ | اسم واضح للغرض والفاعل والمدخلات والمخرجات. |
| هل حُددت الصلاحية؟ | Policy أو Gate أو سبب موثق لعدم الحاجة. |
| هل حُددت طبقة كل ملف؟ | Request، Controller، Service/Query، Resource، Model، Event، Job. |

## أثناء التعديل

| المجال | معيار القبول |
|---|---|
| Controller | لا يحتوي استعلامًا مركبًا أو قواعد أعمال متعددة الخطوات. |
| Request | يحتوي قواعد التحقق والتفويض الأولي فقط. |
| Resource | يحول البيانات ولا يغير قاعدة البيانات أو ينفذ بثًا. |
| Service | يعزل حالة الاستخدام المركبة ولا يعتمد على HTTP مباشرة. |
| Query | للقراءة والتقارير فقط، ولا يغير حالة البيانات. |
| Policy | يتحقق من ملكية المورد أو علاقة المستخدم به. |
| Event/Broadcast | يعلن الحدث ويرسل الحد الأدنى من البيانات المسموح بها. |
| Job | يعالج العمل المؤجل ويمكن إعادة تنفيذه بأمان. |
| Realtime | WebSocket داخلي في Laravel للإشارة والحالة فقط، وWebRTC/DataChannel P2P للتفاعل المباشر. |
| P2P | لا Media Server ولا Relay ولا Proxy ولا STUN ولا TURN ولا طرف ثالث. |
| Database | كل تغيير Schema في Migration، مع FK وUnique وIndex مبررة. |
| Data contract | كل حقل في OpenAPI له تمثيل واضح في Model/Resource أو سبب موثق لكونه مشتقًا. |
| Privacy | الإسقاط العام لا يحتوي الحقول الحساسة، والـPolicy تحدد علاقة الطالب بالمعلم. |
| Traceability | كل سجل رسمي يملك معرفًا ووقتًا ومصدرًا ومسارًا للتدقيق عند الحاجة. |

## بعد التعديل

1. نفذ فحص الشجرة مرة أخرى وتأكد من أن الملفات في المسارات المعيارية.
2. شغّل اختبارات Feature وUnit المتعلقة بالميزة.
3. اختبر النجاح، الفشل، عدم الصلاحية، البيانات الناقصة، والتكرار.
4. راجع أن الاستجابة تستخدم Resource ولا تكشف حقولًا داخلية.
5. راجع أن العمليات الرسمية قابلة للتتبع وأن الأحداث اللحظية لا تستبدل الحفظ.
6. افحص أن الصوت والفيديو لا يمران عبر Laravel أو WebSocket، وأن الاتصال المباشر لا يستخدم STUN أو TURN أو Relay.
7. افحص أن WebSocket موجود داخل `app/Realtime` ولا يعتمد على مزود أو مكتبة خارجية.
8. طابق الجداول والحقول والعلاقات مع `DATABASE_SCHEMA_CONTRACT.md` و`database_schema.sql`.
9. اختبر FK وUnique وCheck وIndex، واختبر بيانات التسجيل قبل القبول وبعده والعضوية الفعالة والتكرار.
10. شغّل سكربت التحقق المرفق عند توفر مشروع Laravel محلي.
11. وثق أي اختلاف عن الشجرة المرجعية، واذكر سبب الإبقاء عليه.

## معايير الرفض

ارفض التعديل أو أوقفه للمراجعة إذا وضع API Resource خارج `app/Http/Resources`, أو Form Request خارج `app/Http/Requests`, أو وُضع منطق أعمال مركب داخل Controller، أو تم تجاهل Policy لمورد يملكه مستخدم، أو استُخدم WebSocket لنقل الوسائط بدل WebRTC، أو أضيف Media Server أو Relay أو Proxy أو STUN أو TURN، أو استُخدم مزود أو مكتبة خارجية للاتصال اللحظي، أو أُنشئ Repository/Service/طبقة إضافية دون مبرر واضح.
